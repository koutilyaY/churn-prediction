Key Insights:
  1. Tenure is strongest predictor
     - Customers < 6mo: 50% churn
     - Customers 24+ mo: 5% churn

  2. Contract type drives churn
     - Month-to-month: 42% churn
     - 1-Year: 11% churn
     - 2-Year: 3% churn

  3. Internet service matters
     - Fiber Optic: 42% churn
     - DSL: 25% churn
     - None: 8% churn

  4. Price weakly correlated
     - Tenure & relationship > price

🎯 THRESHOLD OPTIMIZATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Optimal Threshold: 0.42 (cost-benefit optimized)
  - False Positive Cost: $500 (wasted retention spend)
  - False Negative Cost: $5,000 (lost customer LTV)

At 0.42 Threshold:
  ✓ True Positives: 75   (correctly identified churners)
  ✓ False Positives: 23  (wasted spend)
  ✓ False Negatives: 43  (missed churners)
  ✓ Precision: 76.5%     (of those flagged, 76.5% actually churn)

Annual Projection (scaling monthly to 12 months):
  ✓ Customers saved: 355/year
  ✓ Value protected: $1.78M/year
  ✓ Retention spend: $177.5K/year
  ✓ Net benefit: $1.6M/year

"I built a churn prediction model for a telecom SaaS company facing $2M 
annual revenue loss from 26.5% customer churn.

Rather than just maximizing accuracy, I took a business-first approach. 
I compared 3 models (logistic regression, random forest, XGBoost) and 
found they all achieved ~0.84 AUC.

The key differentiator was threshold optimization. The default 50% 
probability threshold is wrong. By analyzing the cost of false positives 
($500 wasted retention spend) vs. false negatives ($5K lost customer), 
I found the optimal threshold at 0.42.

At 0.42, the model identifies 355 customers/year who would have churned, 
protecting $1.78M in annual value. After accounting for $177.5K retention 
spend, that's a $1.6M net annual benefit.

I built an interactive Streamlit dashboard so non-technical stakeholders 
can input customer profiles and see churn risk scores. The code is fully 
reproducible with notebooks for EDA, feature engineering, modeling, and 
business impact analysis.

The GitHub repo demonstrates end-to-end data science: problem framing → 
analysis → defensible decisions → measurable business value."
